# Case 02 · 原生报告生图

[English](README_EN.md) · [运行示例](run.js) · [完整视觉 Prompt](visual-prompt.js)

## 一句话定位

先让文本模型生成完整、可校验的报告，再让图片模型依据报告原生完成图文协同设计。

## 适合什么场景

- 信息密度高、图与文字必须共同构图的个性化报告；
- 模板槽位填充会显得拼装、拥挤或缺乏内容理解；
- 能接受图片模型生成后的 OCR 与定向编辑成本。

## Hybrid 分工

| 模型负责 | 程序负责 |
|---|---|
| 文本模型生成候选报告 JSON | 检查 Schema、完整性、字数与敏感信息 |
| 图片模型融合报告、人物、场景与文字 | 选择视觉叙事并组装完整生成任务 |
| 图片模型定向修正错误区域 | 接入后可执行 OCR、视觉门禁、重试与保存 |

## 标准流程

```text
冻结上游事实 → 报告 JSON → 程序校验 → 选择视觉叙事
→ 原生带字图 → OCR/视觉检查 → 定向编辑 → 再次检查 → 保存
```

```bash
npm run example:native-image
```

示例包含一份可交给图片 Provider 的完整视觉 Prompt。运行脚本使用 Mock URI 和模拟 OCR
文本，只验证任务中包含 `【共生纪 开源样例】`，不会调用图片 API、生成图片、执行真实 OCR、
定向编辑或保存文件。真实 Provider 与 QA 引擎需要由宿主接入。
