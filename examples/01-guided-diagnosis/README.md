# Case 01 · 受控诊断 Agent

[English](README_EN.md) · [运行示例](run.js) · [场景定义](scenario.js) · [Agent 协议](protocol/AGENT.md)

## 一句话定位

让 LLM 自然地理解和追问，让程序可靠地控制字段、分支 Loop、成本与最终冻结。

## 适合什么场景

- 工作诊断、需求澄清、方案配置和复杂表单补全；
- 用户表达自然、答案可能跨多个字段；
- 必须避免模型偏离主线、无限追问或自行宣布完成。

## 责任边界

| 模型负责 | 程序负责 |
|---|---|
| 理解用户原话并提出候选字段 | 校验候选字段及其证据 |
| 根据当前缺失字段生成一个问题 | 决定当前分支是否完成 |
| 在收到纠偏指令后收束对话 | 累计无进展、Token 与人工接管状态 |
| 基于冻结数据生成候选报告 | 冻结事实并阻止下游反向改写 |

## 30 秒运行

```bash
npm run example:diagnosis
```

示例使用两条虚构回答完成两个分支，不需要 API Key。接入真实模型时，Provider Adapter
只能调用 `recordUserTurn`、`submitFields`、`recordNoProgress` 等公开动作，不能直接写 Repository。

## 输入与输出

- 输入：场景定义、用户消息、来源回合 ID、模型提出的候选字段、模型调用 Token 用量；
- 输出：当前分支、缺失字段、下一问题、纠偏或转人工动作，以及带证据引用的冻结对象。

## 关键行为

- 字段只有“已获取”或“尚未获取”，不设置模糊完成度；
- 必填字段可用前，当前分支持续 Loop；
- 连续两次无进展触发纠偏，纠偏后再次无进展转人工；
- 无进展计数在进入新分支时清零；
- Token 达到宿主配置的总预算后硬停止，但不把用量告诉用户；
- 付费、访问次数和渠道权限由宿主应用决定，不写死在本案例中。

## 开源边界

本例字段完全虚构，用于展示机制。作者基于同类机制开发的商业化诊断应用不属于本仓库。
