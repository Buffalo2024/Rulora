# Rulora PDCA Management Agent 设计备忘

状态：长期设计保留，等待独立项目开发。

## 定位

Rulora PDCA Management Agent 是 Rulora 生态下的独立 Agent，不是 Report Agent 的普通
场景包。它通过结构化访谈，帮助用户从理想状态、现实情况和关键差距出发，形成可执行、
可检查、可持续复盘的管理循环，并为未来的人机协同保留专家审核和持续跟踪接口。

不得将项目命名为 Honda Agent，也不得暗示获得本田官方授权。方法说明可以表述为：参考
公开的 PDCA 与 DST-PDCA 方法，并由具有实际管理经验的贡献者持续完善。

## 与 Report Agent 的关系

```text
Rulora PDCA Management Agent
  负责访谈、诊断、问题澄清、行动规划、跟踪和复盘
                  ↓ 标准结构化结果
Rulora Report Agent
  负责模板选择、PNG/PPTX 渲染、质量检查和文件交付
```

## 方法主线

```text
Draw   描绘理想状态
See    客观观察当前事实
Think  识别差距、关键课题和优先级
Plan   制定可验证的计划
Do     记录责任人、时间和实际执行
Check  用事实比较预期与结果
Action 修正、标准化或开启下一轮循环
```

Agent 必须区分事实、判断、假设和行动。模型不能自行宣布问题已经找到、原因已经确认、
对策已经有效或 PDCA 已经完成；这些状态只能由程序根据字段、证据和用户确认推进。

## 首批任务路线

1. DST-PDCA 咨询分析：面向目标和问题尚不清晰的用户；
2. 问题解决 PDCA：面向质量、延期、投诉、成本和协同异常；
3. 计划推进与复盘：维护目标、行动、责任人、期限、偏差和修正；
4. PDCA 质量审查：检查既有方案是否缺失事实、原因、验证或标准化。

## Hybrid 职责

模型负责理解自然表达、识别矛盾与缺失、生成针对性追问、归纳候选课题、解释计划与结果
关系。程序负责阶段状态、必填字段、证据绑定、行动期限、检查点、回退规则、重试、人工
审核和循环关闭。

## 专家知识包

专家经验不得只写进一个长 Prompt，应版本化保存为：

```text
knowledge/
├── method/
├── question-patterns/
├── decision-rules/
├── review-rubrics/
├── anti-patterns/
├── cases/
└── terminology/
```

重点沉淀每阶段追问、不可推进回答、常见误区、事实与判断区分、课题与对策区分、回退和
转人工条件，以及脱敏的优秀与不合格案例对照。

## 首批验证案例

- 项目延期：验证完整 DST-PDCA；
- 客户投诉反复发生：验证问题定义、原因和对策检查；
- 部门目标无法落地：验证方针展开、行动跟踪和周期复盘。

每个案例应保留原始咨询、追问、用户补充、阶段状态、被拒绝的推断、结构化 PDCA、行动
计划、检查结果和下一轮修正。

## 未来开发入口

开发时先定义阶段状态机、任务协议、专家审核协议和标准输出 JSON；随后完成一个项目延期
端到端案例，再接入 Report Agent 生成分析长图、单页管理汇报、行动计划和复盘报告。
