# 模型与程序的职责

**让模型负责理解与创造，让程序负责控制、验证与交付。**

- LLM：理解证据、开放语义推理、独立判断、候选选择。
- Program：状态、字段合同、统计、候选池、预算、门禁、最终交付。
- Recovery：恢复明确的 JSON/Markdown 载体，不推断业务答案。
- Adapter：按显式映射处理别名与确定性类型，不改变业务结论。
- Reviewer：选择程序已有候选，不把多个方案拼成新答案。
- Loop：网络重连、合同修订、业务广播分别计数、有界停止。
- Checkpoint：对成功结果进行匹配校验后复用；不是承诺外部副作用绝对只执行一次。
- Improvement：客观反馈用于下一版本，不在当前运行中自行改规则。

这些是项目设计边界，不代表安装 Core 就自动拥有所有实现。
例如完整群体决策的模型调用检查点属于场景，而 Core 只内置 MemoryRepository 和工作流状态恢复接口。

## 组合方式

在模型调用后加入 OutputBoundary；在宿主重试逻辑中记录 LoopControl；
群体候选经过业务验证后，再交给 CollectiveControl 冻结与选择。
一个 Agent 可以使用多个组件，多个 Agent 也可以共享由宿主管理的流程。

程序验证“结构符合合同”和模型判断“语义成立”是不同的事情。
把准入条件写成程序断言，并不能凭空证明证据真实或业务方案最优。
