# Rulora 场景仓库与项目边界

Rulora 是可以嵌入 Agent 的控制组件。解决具体用户任务的案例作为独立开源项目发布，
用于展示控制思路，不构成必须安装的生态。

## 如何判断是 Agent 还是场景包

当多个任务共享主要执行底座，只在时间周期、行业规则、数据源、模板或输出格式上存在
差异时，它们属于同一个 Agent 的场景包。只有在核心状态、工具边界、交付责任和失败语义
都明显不同时，才应考虑创建新的 Agent 项目。

```text
Rulora
├── 可插拔控制组件
└── 独立场景仓库
    ├── Rulora Report Agent
    │   ├── 跨境电商政策日报
    │   └── 新能源汽车出海周报
    ├── Rulora AGTI
    │   └── 20 道题、24 型身份与受控诊断
    └── Rulora Collective Decision
        └── 虚构企业信贷风险研究案例
```

日报和周报不是独立 Agent。Report Agent 通过任务路由选择场景、周期、输入模式、区域、
模板和交付格式，并复用结构化、验证、渲染和 QA 底座。

## Rulora Report Agent

Report Agent 将公开来源转换为经过验证的 PNG 长图。当前场景为：

1. 跨境电商政策与平台规则日报：按决策主题、适用范围与证据状态组织，不预留地区版位；
2. 新能源汽车出海周报：按市场准入、贸易措施、供应链等决策主题组织。

[Rulora Report Agent](https://github.com/Buffalo2024/Rulora-Report-Agent) 已作为独立 Alpha
仓库发布，并按以下条件持续审计：

- 克隆后可以按照文档独立运行；
- 至少一个场景具有真实、可复现的端到端交付；
- 包含示例输入、结构化中间结果、最终成品和 QA 报告；
- 模型生成的事实、数字和结论受到证据或输入约束；
- 模板溢出、字段缺失或质量失败能够被程序拒绝；
- 不包含密钥、私有数据或无权分发的资产。

## Rulora AGTI

[Rulora AGTI](https://github.com/Buffalo2024/Rulora-AGTI) 公开确定性的 20 道题计分规则、
24 型身份映射、受控诊断状态机、24 张身份视觉图、24 张报告原型图和每型 A/B 设计协议。
它不是心理测验、医疗诊断、招聘筛选或影响个人权益的自动化决策工具。

## Rulora Collective Decision

[Rulora Collective Decision](https://github.com/Buffalo2024/Rulora-Collective-Decision) 使用虚构企业
案例展示三席独立判断、候选冻结、法定人数、受限 Reviewer、检查点和恢复。本案例缺少足够的
标注与独立评估数据，不能用于真实授信、拒贷、定价或其他高影响决策。

## 官方 Agent 的最低要求

官方 Agent 应当：

- 明确模型负责什么、程序负责什么；
- 提供机器可读的 Agent Manifest 和任务输入；
- 将失败、重试、拒绝和人工接管表示为显式状态；
- 交付主文件以及来源、证据或数据范围说明；
- 提供机器可读的质量检查结果；
- 为场景路由、输入验证和交付门禁提供自动化测试；
- 使用版本化场景、模板和交付契约。

## 社区扩展方式

行业贡献者可以在不修改 Agent 底座的情况下贡献数据源注册表、地区 Profile、分类体系、
字段映射、验证规则、模板和示例数据。Rulora 主仓库不收集只有 Prompt、无法运行或无法
验证的 Agent 条目。
